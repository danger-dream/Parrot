中国区积分明细直接展示在账户详情内，包较多时仍在完整详情中分页；旧消息里的“积分明细”按钮兼容回到详情，不再打开二级页。中国区 `签到/领额度` 内安排活动执行、自动签到和记录。国际区列表和详情不套用积分／资源包界面：不显示积分、资源包、计费类型、空包提示、未获取占位、空的使用量标题及相关分页、刷新、签到、领取按钮；身份、模型、本地调用统计、TPS、金额和通用账户操作保留。中国区和国际区正常账户均显示“刷新 Token”，仅认证失效时在同一位置替换为“重新登录”，不同时显示两个按钮。国际区旧积分、刷新额度、活动及确认按钮只返回账户详情，不查询或提交领取，也不弹出查询中提示。后端真实额度不足处理保持不变，空资源包不视为余额零，不编造免费或无限额度。

资源包最终到期优先读取已有 `PackageEndTime/EndTime`，缺失时读取 `DeductionEndTime`（毫秒时间戳）；`CycleEndTime` 仅表示本周期结束，不能替代最终到期。未知时间不编造，Token 有效期继续单独展示。

WorkBuddy 新增账号仅提供“中国区登录”“国际区登录”，不提供 JSON／手动凭据导入；已有两区账户不受影响。管理 API 的 WorkBuddy 能力说明与此一致：`browserLoginRealms=[cn,global]`、`importRealms=[]`、`clientProfilesByRealm={cn:cli,global:workbuddy-cli}`；国际区只提供 `workbuddy-cli` 新增入口，原 `clientProfile=cli` 保留为中国区兼容默认值。旧 IDE 新增按钮和接口请求不再建立登录流程，已有 IDE 账户仅保留原路线重登兼容。账户列表只显示个人／企业、区域和模型数，技术路线放在详情中，不把产品路线当作账户名称。

国际区入口使用 `www.workbuddy.ai`、`platform=CLI`；中国区使用原 `cli` 路线。两区统一为：点击入口 → 打开官方授权链接 → 后台约每 5 秒自动检查 → **确认身份后直接保存并显示身份**。保留“检查登录”作为唤醒同一后台任务的兜底，不再出现保存／覆盖确认按钮；同身份只更新授权并保留原设置，不替换别的身份。身份查询暂不可用时继续查询身份，不重新获取 Token；过期／取消后停止。旧结果不能覆盖已切换的页面，不能清掉新的输入状态。保存后的模型／额度同步失败不回滚授权。已有国际区 `cli` 账号仍保留原域名／刷新方式，不混用路线。

管理 API 调用方继续周期调用 `POST /oauth/login-flows/{flowId}/poll`（建议 5 秒一次）；首次身份确认成功即执行持久化，返回 `status=completed`、`accountId`、`saveStatus=created|replaced`、`revision` 和公开的 `accountPreview`。`/complete` 对该 WorkBuddy 流程保留兼容幂等返回，不必再调用；重复轮询／完成不会重新保存，更不会在账号已删除后重新添加。流程及完成结果始终绑定发起者与 flowSecret，公开响应不含 Token。其他供应商的完成／覆盖确认契约不变。

### 积分空状态与查询反馈

- 上游成功响应中的 `TotalCount: 0, Accounts: null` 是明确的空资源包结果，归为 `status=empty, complete=true`；缺失 Accounts、非零计数配 null、错误结构仍按异常处理。
- 中国区列表／详情／活动页显示“当前未查到有效资源包”。国际区不显示该积分区块。两区都不把空包编成余额 0，不据此自动禁用或解禁账户，也不回填旧资源包余额。中国区真实失败时仍保留已有成功值并标注旧快照。
- “查询活动/余额”和详情“刷新额度”均即时答复“查询中…”，原消息先显示查询进度；上游查询在后台执行，不阻塞 TG 后续操作。结束后保留结果、北京时间及区域对应的只查询说明；若用户已切换该消息的页面，不再用旧查询结果覆盖新页。即使余额不变，再点也有进度反馈。
- 活动页直接显示积分摘要、数据更新时间及已获取的计费类型；部分失败显示具体组件和安全的错误类型／HTTP／业务码。查询异常不会再被随后重绘的普通页面覆盖，原始异常或上游敏感正文不回显。
- 中国区查询说明为“本次仅查询，未执行签到”。国际区旧查询入口只返回账户详情，不显示查询进度、结果或积分反馈。除移除国际区不适用项外，通用按钮与执行确认顺序保持原样。

### 客户端身份与模型来源

- WorkBuddy 请求补 `X-IDE-Type/Name/Version`：中国区及存量国际区 CLI 为 `CLI / 2.63.2`；国际 IDE 聊天为 `IDE / 2.108.1`，认证／额度查询沿原 `IDE / 2.63.2`。国际 IDE 模型查询单独使用 `CodeBuddyIDE / 4.12.1`，User-Agent 为 `CodeBuddyIDE/4.12.1`。CLI 聊天补 `X-Agent-Intent: craft`，IDE 聊天保留 `x-codebuddy-request: 1`。不换主机或混用 Token，刷新凭据仍只发刷新端点。
- 聊天最前补 `system: You are CodeBuddy Code.`；原 system/developer 原样保留，不删除、不迁到 user、不清理正文，也不强制 high。已有相同首条身份提示不重复注入。这是客户端兼容身份提示，不宣称能保证不被识别。
- 中国区及存量国际区 CLI 主模型源仍为 `/console/enterprises/personal/models`；只有 HTTP 404/405 才请求同账户／同主机／同 profile 的 `/v3/config`，取 `agents[name=cli].models` 与未禁用的模型记录交集。不合并两个来源；401/403/429/5xx、业务错误或 200 缺目录不会触发切源。失败保留最后成功目录及用户选择。

### 账户类型与模型倍率

- 官方登录返回的 `account.type` 独立保存为 `workbuddy_account_type`，不覆盖 Parrot 的供应商字段 `type=workbuddy`。列表区分个人、个人 Pro、企业版、专享版、私有部署；详情展示官方原值。未获取时只保留个人／企业身份范围，不凭积分包或模型是否免费推断会员套餐；未知类型不默认为个人版。
- 官方模型目录的 `credits`（如国际区 `x0.00`、中国区 `x0.11 credits`）归一为账户专属 `workbuddyCreditMultiplier`。模型中心列表和每个来源的详情均显示倍率；明确零值标“免费”，缺失、空值或非法值标“倍率未知”，不以缺失或舍入结果判断免费。
- 同一模型在不同区域或账户可有不同倍率。来源筛选只展示该来源；全部来源展示不同倍率并提示按账户区分，详情保留具体账户归属。倍率与通用美元／百万 Token 定价独立，不互相换算，不用于改写请求模型 ID 或启停选择。刷新上游模型时更新倍率，不使用静态免费名单。

### 自动签到：两轮机会，而非两次提交

- 默认关闭、仅中国区，用户开启后按北京时间 **09:05 主轮＋21:05 补漏轮**检查；每轮最多 3 次机会，间隔至少 15 分钟。切入晚轮时有独立检查预算，不被早轮耗尽或退避挡住。
- 已成功或上游确认已签：不重复提交。活动有效且明确未签：才可提交。
- 早轮 pending/unknown：晚轮仅查询核对；即使查询仍显示未签，也不自动重放可能已提交的请求。
- 早轮明确拒绝：晚轮先重新查询活动与签到状态，再允许一次新尝试；晚轮再次明确拒绝后，重启调度器也不能自动重复该晚轮提交。
- 手动停用或认证失效时暂停；自动试用申请仍不支持。活动页与开启确认页说明两轮规则。API 新增 `autoCheckinTimes/scheduledTimes=[09:05,21:05]`，原单值时间字段保留兼容。
